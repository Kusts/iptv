# Admin Guide — Customer Support

> Status: Draft baseline  
> Versão: 0.14  
> Data: 2026-09-22  
> Review: Auto-reviewed v0.14 — context confirmation, operational signals, research and refund HITL added.

Open/reuse the Ticket and check active Incidents/Operational Signals first. Present volatile context already known to the customer for confirmation (for example device/app) instead of asking from zero. Authoritative payment/plan/expiry comes from system state.

Follow ranked troubleshooting and record every attempt/outcome. If internal knowledge is insufficient, Support Research may consult authoritative web sources, relevant communities/repos and YouTube transcripts when allowed; all external content remains UNTRUSTED until validated. Repeated independent signals may create Incident Candidate.

A successful one-off fix becomes Candidate Knowledge, not VERIFIED. Global learning must be sanitized and strip PII/secrets/tenant identity.

Refund requests always create Human Review. IA may gather evidence and continue the conversation when safe, but a human decides/executes refund.

## Escalation rule

If the interface presents a state/action not explained by canonical Domain/SPEC/Policy, stop and report documentation drift rather than improvising.
