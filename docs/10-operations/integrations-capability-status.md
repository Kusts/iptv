# Integrations Capability Status

> Status: Canonical engineering register (per capability)
> Scope: every external integration seam this repository ships, one row per capability
> Source of authority for the CINEVISION runtime states: `docs/04-specs/integrations/cinevision-runtime-hardening.md` §23 (`UNCERTIFIED | SANDBOX_CERTIFIED | CERTIFIED` in `platform.capabilities.certification_status`)

## How to read this document

- **Statuses are per capability, never a global product status.** A `LAB_VALIDATED` read capability says nothing about the write capability of the same provider, and `IMPLEMENTED` infrastructure says nothing about any live gate. Never summarize this file as "the platform is certified".
- **Only OPERATOR-recorded evidence promotes a status.** Code, tests, fixtures, fakes, `.env` configuration and a configured credential are *not* evidence of a live gate. A status is promoted only when the operator ran the procedure in `docs/15-implementation-baseline/10-integrations-certification.md` (or the gate named in the row) and recorded its result in the Fase 6 evidence template / this file.
- **When the evidence is ambiguous, the more conservative status wins.** `IMPLEMENTED` < `LAB_VALIDATED` < `LIVE VALIDATION REQUIRED` < `CERTIFIED`; `DEGRADED` and `CERTIFIED_WITH_LIMITATIONS` describe an already-promoted capability that regressed.
- This register does **not** mutate `platform.capabilities`. The `availability` / `certification_status` rows remain the runtime authority and are changed only through a migration + event, never from documentation.
- Status vocabulary (exact): `IMPLEMENTED`, `LAB_VALIDATED`, `LIVE VALIDATION REQUIRED`, `CERTIFIED`, `CERTIFIED_WITH_LIMITATIONS`, `DEGRADED`.
- Vocabulary mapping (read once, so the two ladders are not mistaken for a third): the plan ladder at the top of `10-integrations-certification.md` is `UNVALIDATED → LAB_VALIDATED → CANARY_VALIDATED → CERTIFIED`, and the runtime `platform.capabilities` ladder is `UNCERTIFIED | SANDBOX_CERTIFIED | CERTIFIED` (SPEC §23, the runtime authority). This register's `IMPLEMENTED` sits **below** the plan ladder's `UNVALIDATED` (it describes code, not evidence), and its `LIVE VALIDATION REQUIRED` is the honest single status for the whole `UNVALIDATED` → `CANARY_VALIDATED` span — those rows still lack live evidence, so naming them "canary validated" would overstate them. `CERTIFIED`, `CERTIFIED_WITH_LIMITATIONS` and `DEGRADED` are shared by all three ladders.

## Reading the rows

- `IMPLEMENTED` = the seam exists in this repository, is wired into the runtime and is covered by automated tests. It says **nothing** about a provider being reachable or correct.
- `LAB_VALIDATED` = someone ran it against a non-production target and recorded the observation (the CINEVISION read pass, the Infisical machine-identity reads). The artifact of that run is named in the row.
- `LIVE VALIDATION REQUIRED` = the contract is either unobserved or implemented but never run against the real counterparty. This is the honest status for every provider **write** capability today.
- `CERTIFIED` / `CERTIFIED_WITH_LIMITATIONS` / `DEGRADED` = reserved for a completed Fase 6 final step (or an equivalent gate) with every evidence field filled. **No capability in this repository holds any of them today.**

## Promotion rule (operational)

1. Run the capability's gate from `docs/15-implementation-baseline/10-integrations-certification.md` (Fase 6 for CINEVISION; the per-provider section for the others) and fill every evidence field of its template.
2. Record the operator, date, environment and the raw observation (no secrets, no customer identifiers/PII) in the Fase 6 evidence block of that document.
3. Update **this row** with the new status, the evidence reference and the next gate — including any recorded limitation that caps the promotion.
4. Only then change the runtime `platform.capabilities` row through a migration + event (`UNCERTIFIED → SANDBOX_CERTIFIED → CERTIFIED`); cleanup failure always blocks promotion.

Unresolved or inconclusive runs are recorded as unvalidated — never silently approved.
