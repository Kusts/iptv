# Incident & Problem Management

> Status: Canonical operations baseline  
> Version: 1.0  
> Review: Auto-reviewed v0.11 — checked for authority, state/event vocabulary, tenant isolation, failure paths and testability.

Ticket = one customer's issue. Incident = current shared operational impact. Problem = recurring/root cause pattern.

Lifecycle includes detection, severity, owner, affected scope, containment, status communication, recovery, resolution, post-incident review and Problem creation when recurring/systemic.

Incident updates may alter support routing and suppress repetitive troubleshooting, but do not rewrite customer/provider state without evidence.

Post-incident review records timeline, root cause when known, contributing factors, missed detection, preventive actions, tests and knowledge/runbook updates.
